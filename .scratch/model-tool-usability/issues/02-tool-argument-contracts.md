# 02 ツール引数の説明・既定値・短い例

Status: ready-for-agent

Spec: [採用9項目の仕様](../spec.md)

## 現状と目的

src/mcp.rsの多くの引数は型だけが定義され、引数の意味をREADMEやモデルの推測へ委ねている。

## 作業範囲

- path/cwdの基準、argv、観測時間、入力mode、request_idの使い分けを引数descriptionへ書く。
- 既定値・境界値・排他条件を実検証と一致させる。
- 頻出の誤用に対する短い例を用意し、追加ツールでも同じ書き方を使う。

## 受入条件

- [ ] tools/listだけから、シェル展開の有無、観測と実行期限の違い、同一依頼の再配送方法を理解できる。
- [ ] 既存の必須引数・ツール名・unknown field拒否を維持する。
- [ ] stdin/停止ACKを実際の消費・実行終了の証明と説明しない。

## 依存と検証

01の後。03/04と共通の語彙・フィールドを揃える。

tests/transport.rsで公開定義と呼出しを確認。通常Chatでの誤引数の往復は別の受入として測る。

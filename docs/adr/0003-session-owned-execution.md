# 作業セッションが実行管理を所有する

2026-10-22の設計第3ラウンドQ8で採用。MCP接続の張り直しでジョブの観測を失わないため、App Serverの元stdio接続、ジョブ状態、保持中の出力を既存の`local-mcp start`へ集約し、`mcp`は既存セッションIPCを通じるfacadeとする。
IPCへ実行要求の中継を追加する負担を受け入れる代わりに、新しいdaemon・外部接続・永続ジョブ台帳を作らず、同じ起動セッションと元App Serverが生存する間だけ再接続後の観測を提供する。
再起動したApp Serverや推測したPIDへ元ジョブを結び直さず、Tunnelの再起動運用は既存chatgpt-mcpの責務に残す。

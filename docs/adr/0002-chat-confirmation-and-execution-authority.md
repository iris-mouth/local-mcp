# 操作確認と固定認可上限を分ける

2026-10-22の設計第2ラウンドQ4で採用。日常の操作確認はChatホストの設定へ委ね、サーバーは既存の認証済MCP接続から届いた要求について、作業セッションとMac側で設定した固定認可上限を検査して実行する。
独自のクリック証明や署名付き承認の仕組みを増やさない代わりに、サーバーは毎回の本人クリックを証明する保証を持たず、モデルの`approved`値、yolo、ツールannotationを実行認可の根拠にしない。
モデルへ固定認可上限を変更するAPIを公開しない。

根拠: 本人の第2ラウンド回答「すべて推奨どおり」、[公式ツール設計](https://developers.openai.com/plugins/plan/tools#plan-safety-annotations)。
